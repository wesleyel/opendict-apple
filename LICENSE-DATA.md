# Licensing of the built dictionary

This repository contains three separately licensed things. Read this before
redistributing a built `.dictionary` bundle.

## 1. Conversion tooling — MIT

`src/build_appledict.py`, `Makefile`, `scripts/update_cask.py`, the workflow, the CSS and the plist
are MIT licensed. See [LICENSE](LICENSE).

## 2. Dictionary data — CC BY-SA 4.0

Every `.dictionary` bundle produced here is a derivative of
[ahpxex/open-dictionary](https://github.com/ahpxex/open-dictionary), which is
itself a derivative of Wiktionary content and is published under
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).

ShareAlike therefore propagates to the built bundle and to anything derived
from it. If you redistribute a bundle you must:

- **Attribute** Wiktionary contributors and `ahpxex/open-dictionary`
- **License alike** — release it under CC BY-SA 4.0, not a more restrictive
  licence
- **Indicate changes** — state that the content was reformatted for
  Dictionary.app

Attribution is carried in three places so a redistributed bundle stays
compliant on its own:

| Location | Mechanism |
|---|---|
| Dictionary.app "About" panel | `DCSDictionaryCopyright` in `src/OpenDictionary.plist` |
| A front matter page inside the dictionary | entry id `front_back_matter`, generated by `src/build_appledict.py` |
| Release notes | emitted by the publish step of the workflow |

Do not strip any of them.

## 3. Dictionary Development Kit — Apple proprietary, not redistributed

The build depends on Apple's Dictionary Development Kit, which Apple ships only
inside *Additional Tools for Xcode* under the Xcode licence agreement. This
repository does **not** vendor it; the build fetches the
[nanoskript/dictionary-development-kit](https://github.com/nanoskript/dictionary-development-kit)
mirror at build time and uses it only to compile the bundle. No part of the DDK
ends up in the published artifact.
